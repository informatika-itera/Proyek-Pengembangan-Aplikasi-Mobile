--- SLIDE 6: ARCHITECTURE ---
Tujuan: Tunjukkan kedewasaan teknis dengan arsitektur yang solid.
Isi:

Pola Arsitektur: Clean Architecture + MVVM
Alur Data:
  [Compose UI] → [ViewModel + StateFlow] → [Repository Interface]
       ↓                                          ↓
  [State/UiState]                    [NewsRepositoryImpl]
                                      ↙             ↘
                           [SQLDelight]         [Ktor + GeminiAPI]
                           (Offline/Local)       (Remote/Network)

Tech Stack Lengkap:
  • Bahasa          : Kotlin (Multiplatform ready)
  • UI Framework    : Jetpack Compose (Declarative UI)
  • Networking      : Ktor Client (HTTP + JSON serialization)
  • Database Lokal  : SQLDelight (Type-safe SQL, auto-generate Kotlin queries)
  • DI Framework    : Koin (Dependency Injection untuk ViewModel & Repository)
  • AI Integration  : Google Gemini REST API (via Ktor POST)
  • CI/CD           : GitHub Actions (android.yml, badge di README)
  • Image Loading   : Coil + Coil-Ktor

Prinsip Kunci:
  • Single Source of Truth: Repository sebagai satu-satunya sumber kebenaran data
  • Separation of Concerns: UI tidak tahu asal data (DB atau API), hanya render State
  • Reactive: UI otomatis ter-update via StateFlow tanpa polling manual

Struktur Folder:
  composeApp/src/commonMain/kotlin/com/itera/news/
  ├── data/          → remote/ (Ktor, DTO), repository/ (Impl)
  ├── domain/        → model/ (Article), repository/ (Interface)
  ├── presentation/  → screens/ (Home, Detail, Bookmark, AddEdit, Settings)
  │                    navigation/ (NavGraph, Screen)
  ├── core/          → di/ (AppModule Koin), network/ (HttpClient), util/

--- SLIDE 7: CHALLENGES & LEARNINGS ---
Tujuan: Tunjukkan refleksi tim atas perjalanan membangun aplikasi ini.
Isi:

CHALLENGES (Hambatan):
  1. Integrasi 3 layer Clean Architecture
     → Sulit menjaga agar UI, Domain, dan Data benar-benar terpisah.
       Setiap tambahan fitur harus melewati semua lapisan dengan benar.
  2. Menstabilkan Format Respons Gemini AI
     → Awalnya AI sering memberikan kalimat panjang yang merusak UI.
       Solusi: Kami menyesuaikan format permintaan API dengan instruksi ketat: 
       "Balas HANYA dengan satu kata: Pro/Kontra/Netral"
  3. Reaktivitas StateFlow dengan SQLDelight
     → Memastikan UI ter-update otomatis saat data berubah di database lokal
       tanpa memanggil API lagi.
  4. Desain Neumorphism di Compose
     → Tidak ada library siap pakai. Harus membuat Custom Modifier sendiri
       dengan shadowColor, highlight, dan offset yang dikalkulasi manual.

LEARNINGS (Pelajaran):
  1. Clean Architecture bukan tentang kerumitan, tapi tentang ketahanan kode jangka panjang.
  2. Cara kita memberi instruksi ke API sangat menentukan stabilitas aplikasi saat berhadapan dengan AI.
  3. Offline-First Repository adalah standar emas aplikasi modern yang peduli pengguna.
  4. Dependency Injection (Koin) secara drastis menyederhanakan testing dan modularity.
  5. StateFlow + Jetpack Compose = UI reaktif yang jauh lebih bersih dari LiveData/Callback.

--- GeminiApi.kt (Implementasi AI Sentimen) ---
class GeminiApi(private val httpClient: HttpClient) {
    suspend fun analyzeSentiment(title: String, description: String): String {
        val prompt = """
            Analisis sentimen berita berikut. Balas hanya dengan satu kata: "Pro", "Kontra", atau "Netral".
            Judul: $title
            Deskripsi: $description
        """.trimIndent()
        return try {
            val response = httpClient.post(
                "https://generativelanguage.googleapis.com/v1/models/gemini-pro:generateContent?key=$geminiApiKey"
            ) {
                header("Content-Type", "application/json")
                setBody(GeminiRequest(listOf(Content(listOf(Part(prompt))))))
            }.body<GeminiResponse>()
            response.candidates.firstOrNull()?.content?.parts?.firstOrNull()?.text?.trim() ?: "Netral"
        } catch (e: Exception) { "Netral" }
    }
}

class NewsRepositoryImpl(private val newsApi: NewsApi, private val db: NewsDatabase) : NewsRepository {
    private val queries = db.articleQueries

    override suspend fun getMbgNews(query: String?): Result<List<Article>> { ... // Ktor fetch }
    override suspend fun saveArticle(article: Article) { queries.insertArticle(...) }
    override suspend fun deleteArticle(article: Article) { queries.deleteArticle(article.url) }
    override fun getBookmarkedArticles(): Flow<List<Article>> {
        return queries.getAllBookmarkedArticles()
            .asFlow().mapToList(Dispatchers.IO)
            .map { entities -> entities.map { it.toDomain() } }
    }
    override fun isArticleBookmarked(url: String): Flow<Boolean> {
        return queries.isArticleBookmarked(url).asFlow().mapToOne(Dispatchers.IO).map { it > 0 }
    }
    override suspend fun updateArticle(article: Article) { queries.updateArticle(...) }
}

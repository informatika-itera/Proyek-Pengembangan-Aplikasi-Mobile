# Versioning and Release Policy

MyBawangGacha uses SemVer-style versions:

- `MAJOR.MINOR.PATCH` for stable releases, for example `1.0.0`.
- `MAJOR.MINOR.PATCH-rc.N` for release candidates, for example `1.0.0-rc.4`.
- Development builds may use manual labels such as `1.0-rc3`, but release workflow input should use SemVer-style names.

## Build metadata

Build metadata is generated by Gradle into:

```text
composeApp/build/generated/build-info/commonMain/kotlin/.../GeneratedBuildInfo.kt
```

This generated file is not source-controlled. It embeds:

- version name
- version code / CI run number
- build profile
- build target
- repository URL
- branch
- commit SHA
- clean/dirty state
- build date
- CI flag
- CI run ID

The About screen reads this metadata through `AppBuildInfoProvider`.

## Version ABI string

The ABI string is intentionally internal-only and must not include external service names.

Current format:

```text
<short-commit>_db<schema>
```

If Git metadata is unavailable:

```text
db<schema>
```

Example:

```text
9d1f90b9_db6
```

## Local build examples

```bash
./gradlew :composeApp:compileAndroidMain \
  -Papp.versionName=1.0.0-rc.4 \
  -PbuildProfile=debug \
  -PbuildTarget=Android
```

## CI

`KMP-ci.yml` runs Android, common tests, and iOS simulator compilation. It embeds CI metadata automatically using GitHub Actions environment variables.

## Release

Use the `Release` workflow manually from GitHub Actions with an input version such as:

```text
1.0.0-rc.4
```

The workflow tests, builds Android/iOS artifacts, creates tag `v<version>`, and publishes a GitHub release.
